# 设计分层与系统职责

原草案分为视觉设计、系统交互和平台契约三层。下表补充职责，用于设计评审；不是对当前代码结构的描述。

| 层 | 负责 | 提供 |
| --- | --- | --- |
| 视觉设计 | Token、字号、留白、图标与组件形态 | 可测的排版约束 |
| 系统交互 | 系统栏、全局按键、导航与临时菜单 | 统一语义输入和命中边界 |
| 平台契约 | 应用声明、画布、保留区与组件宿主 | 拟议元数据与运行时边界 |
| 驱动适配（补充） | 显示 / 触摸旋转、刷新模式与硬件能力 | 实测能力与完成状态 |

## 绘制、输入与刷新所有权

系统拥有系统栏的绘制、输入与刷新；应用拥有分配画布中的业务内容；小组件拥有宿主分配区域中的本地布局。系统统一管理临时菜单、截图和全局按键，应用自定义菜单只替换菜单内容。刷新模式选择归系统与驱动，应用表达状态变化和清理意图。

| 场景 | 系统 / 宿主职责 | 应用 / 小组件职责 |
| --- | --- | --- |
| 应用进入 | 分配画布、系统栏与保留区 | 在有效范围内完整排版 |
| 页面切换 | 统一返回与输入隔离 | 新页终态、位置恢复和变化区域 |
| 菜单关闭 | 恢复原覆盖区域与输入 | 恢复原内容和有效状态 |
| 小组件替换 | 标题、尺寸、裁剪与移除恢复 | 仅绘制本地内容 |
| 字号或设备变化 | 提供新矩形与能力 | 重新排版和分页 |
| 显示更新 | 合并与选择刷新策略 | 不自行控制全局刷新节奏 |

实际模块名、函数签名、线程、安全隔离、资源预算和生命周期尚未核实，未来实现文档应链接真实代码。
