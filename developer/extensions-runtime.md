# 插件和锁屏是怎样运行的

这篇先解释概念和运行过程，不要求你会 C 或 ESP-IDF。想立即动手，可先读[第一个插件](/developer/plugin-tutorial)或[第一个锁屏](/developer/lockscreen-tutorial)，遇到概念再回这里查。适用固件范围见[扩展开发总览](/developer/extensions)。

## 一段 Lua 为什么能在设备上工作

固件已经包含 Lua 解释器。解释器负责读懂 `.lua` 里的语句，保存变量、判断条件、执行函数。你制作插件时提供源文件，设备启动插件时读取它，不需要把每个插件重新编译进固件。

但是，“能执行 Lua 语句”和“能操作设备”是两件事。画字、读取电量、保存存档的能力由固件另外提供，称为 **API（应用编程接口）**。例如：

```lua
ui.text(24, 32, "你好", 32, 0)
```

这句话请求固件在画布位置 `(24, 32)` 画出“你好”，字号 32 像素，颜色为黑色。`ui` 是固件提供的一组界面功能，`text` 是其中的画字函数，括号里是本次调用要用的参数。

调用过程如下：

```text
你的 main.lua 调用 ui.text(...)
            ↓
Lua 接口检查参数和当前是否允许绘图
            ↓
小纸 Pico 适配代码把局部坐标换成屏幕坐标
            ↓
字体绘制器把字写入内存中的待显示图像
            ↓
系统显示队列在刷新时把图像送到墨水屏
```

插件不能拿着这个接口随意访问网络、读整张 SD 卡或控制蓝牙。它能做什么，取决于固件为这类脚本提供了哪些 API。这种受限制的运行空间叫**沙箱**。**宿主**就是负责加载脚本、提供 API 和调用脚本的固件代码。**VM** 在本文指一个 Lua 运行实例；创建它会建立本次运行的变量和函数环境。

## 普通插件从打开到关闭

以一个点击计数器为例：

1. **发现入口**：系统扫描 SD 卡插件目录，把合格目录或 `.jrpack` 放进列表。此时不是让所有插件在后台运行。
2. **读取源码**：你点开计数器，系统读取它的 `main.lua`，建立新的 Lua 实例并放入允许的 API。
3. **执行顶层代码**：例如 `local count = 0` 建立计数变量，函数定义登记以后要执行的代码。文件最后返回一个表，告诉系统标题和各个回调在哪里。
4. **初始化**：系统读取标题、导航信息，计算可用画布，再调用可选的 `on_open()`，适合读取存档。
5. **第一次画图**：系统调用必需的 `on_draw()`，计数器画出数字和按钮。
6. **处理操作**：点击发生时系统调用 `on_event(...)`。计数器修改数字；回调结束后系统安排重绘，再次调用 `on_draw()`。
7. **定期检查**：插件页面活动时，系统约每 100 ms 调用可选的 `on_tick(now_ms)`。它适合检查是否到了更新时间，但没有变化时不必刷新。
8. **退出**：系统返回或脚本请求退出后，正常情况下调用 `on_close()`，然后销毁实例。下次打开会重新从入口开始。

### 回调是谁调用的

**回调**是你写好、交给系统在合适时机调用的函数。你定义 `on_draw`，系统在需要显示时调用它；你不需要自己写一个无限循环不断调用它。

```text
用户点击画布
    ↓
系统确定这不是顶栏返回等系统操作
    ↓
on_event("tap", 局部x, 局部y, 0)
    ↓
插件把 count 从 3 改为 4
    ↓
宿主安排重绘，调用 on_draw()
    ↓
屏幕显示 4
```

函数名称要与约定完全相同。`onDraw`、`draw` 都不会被当成 `on_draw`。普通插件必须提供 `on_draw`，其余回调按需实现。

### 为什么退出后变量没了

`local count = 4` 保存在这次 Lua 实例的内存中。实例销毁，变量就不存在了。要跨启动保存，需要用 `storage.write` 把字符串写入插件私有存档，下次用 `storage.read` 读回。

保存失败时仍应允许用户操作和退出。不要把重要保存只放在 `on_close`：程序报错后，系统可能直接停止实例，不再执行 Lua 清理函数。本地包、目录和市场安装的存档差异见[打包说明](/developer/extension-packaging#installation)。

## 锁屏从锁定到解锁

锁屏先由系统管理“现在是否已经锁定”，模板只负责要显示的内容。它可以有两层：

- **静态层**：JSON 说明背景、图片和文字怎么摆放，系统读取并组合成画面。没有 Lua 也能工作。
- **动态层**：可选 Lua 在指定矩形内画时间、通知等。模板声明运行时机和检查间隔，系统负责调度。

### 进入锁屏时发生什么

```text
用户触发锁定 / 用户空闲时间达到设置值
    ↓
系统保存阅读状态、暂停翻页并准备 SD 卡资源
    ↓
读取当前 .lspack 内的 lockscreen.json 和 images.json
    ↓
检查配置、加载图片和字体，形成静态场景
    ↓
按 when 决定是否创建 Lua，并执行第一次绘制
    ↓
提交初始锁屏画面；显示成功后进入已锁定状态
```

**场景**就是这次锁屏所需的背景图像、文字布局以及脚本配置。加载是有失败分支的：例如图片缺失、PNG 编码不支持或内存不足时，系统可显示默认静态锁屏；不能把导入成功当成所有运行条件都已经验证。

### 锁住以后是谁让时钟更新

`when: "locked"` 会启用周期运行。硬件计时器到期后通知系统主循环，主循环再执行 Lua 和刷新；计时器中断本身不运行你的 Lua。

```text
初次画面完成
    ↓ 等待 interval_ms
系统调用 on_tick(now_ms)，再调用 on_draw()
    ↓
按脚本刷新请求或默认策略更新屏幕
    ↓ 刷新结束后再等待 interval_ms
下一次调用
```

因此，`interval_ms: 60000` 是等待 60000 毫秒，也就是 60 秒，然后还要花时间执行脚本和刷新屏幕；它不是保证精确对齐每分钟的第 0 秒。模板应每次读取系统时间，不能假定“回调执行一次就刚好过去一分钟”。ANCS 通知内容变化也可以触发更新，并不一定等到周期到期。

### 解锁时会不会留下后台程序

系统停止锁屏定时器，销毁 Lua 实例，释放场景、图片缓存等资源，恢复原来的字体和显示方向，重新绘制此前界面。`before_open` 模式会先显示一段解锁前内容，再在 `hold_ms` 后完成恢复。模板没有自行控制电源、跳过解锁流程或常驻后台的权限。

锁屏和深睡眠也不是同一概念。画面停住不表示所有系统任务停止；周期脚本、通知服务和系统休眠策略仍会影响耗电。

## 画布、内存图像和刷新

**画布**是脚本允许画图的矩形。坐标原点在左上角，向右 x 增大，向下 y 增大；单位为像素。

普通插件的画布位于系统栏之间。小纸 Pico 默认尺寸下，状态栏占 40 px，顶栏占 64 px，所以插件画布顶部在屏幕 y = 104。脚本调用 `ui.text(24, 32, ...)` 时，实际位置会由系统映射到屏幕约 `(24, 136)`；你不应自己再加 104。

锁屏 Lua 的画布由 `area` 指定。例如 `area` 左上角在设计坐标 `(48, 800)`，在设计和设备尺寸相同的情况下，脚本 `(16, 16)` 就对应屏幕 `(64, 816)`。不同分辨率时，先由系统缩放 area，再把 Lua 坐标当作区域内的实际像素。

**framebuffer** 是内存里保存待显示像素的区域。绘图函数修改它；**刷新**才让墨水屏显示修改后的内容。改了变量并不会自动改变像素，画好了像素也不等于面板已经更新。

| 所处阶段 | 你通常做什么 | 对应操作 |
| --- | --- | --- |
| 数据变化 | 更新内存变量 | `count = count + 1` |
| 需要重新画 | 请求系统安排绘制 | tick 中的 `ui.invalidate()`；输入事件后宿主也会安排重绘 |
| 绘图回调 | 用当前数据画像素 | `on_draw` 中调用 `ui.rect/text` 等 |
| 提交显示 | 请求整屏或局部刷新 | `ui.refresh(...)`；`ui.clear` 也隐含全灰请求 |

**局部刷新**表示只更新矩形范围，适合小数字、小图标；**全屏刷新**更新整块屏幕，常用于整体布局变化或残影清理。黑白与灰度、全刷与局刷是两组不同选择，最终波形由系统显示适配决定。使用入门例子时先保证正确显示，再按[绘图详解](/developer/lua-plugin-ui)缩小刷新区域。

## 为什么插件和锁屏的 API 不一样

普通插件处理用户交互，可读取设备状态和自己的存档。锁屏通常在用户不操作时显示内容，系统只给它受限的时间、变量、诗句、通知快照和包内图像能力。

例如普通插件写 `clock.now()` 会因为没有 `clock` 接口而报错；锁屏写 `storage.read()` 同样不可用。代码后缀都是 `.lua`，不表示可原样互换。

**只读快照**指一次调用拿到当前资料的一份 Lua 表。例如 `ancs.notifications()` 返回通知数组；修改数组不会删除手机通知，也不会向手机发送命令。想拿新资料，需要在下一次回调中重新读取。
