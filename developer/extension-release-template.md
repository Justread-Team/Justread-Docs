# 扩展发布文档模板

本页供锁屏和插件作者复制到自己的项目 README 或发布说明中。它是交付文档模板，不是要装进 `.lspack` 的资源文件，也不增加固件 schema 字段。接口依据见[插件 API](/developer/lua-plugin-api)、[锁屏规范](/developer/lockscreen-development)及[打包安装规范](/developer/extension-packaging)。

## 应写清的内容

| 内容 | 普通插件 | 锁屏模板 |
| --- | --- | --- |
| 兼容性 | 固件版本/提交、硬件、画布、触摸依赖 | 固件版本/提交、硬件、方向、设计尺寸和 Lua area |
| 接口依赖 | 生命周期、事件、device/reader/storage、导航 | JSON 字段、when、clock/config/poetry/ANCS、glyph/image |
| 资源部署 | 是否必须目录安装，市场仅入口的影响 | 包内引用、字体来源、许可证、市场是否接受 |
| 刷新/功耗 | tick 节流、全刷或局刷策略 | interval/hold、刷新模式、BLE 和软休眠影响 |
| 数据与故障 | 存档路径、失败返回、退出与恢复 | 缺时间/变量/诗库/通知时的静态兜底、解锁恢复 |
| 交付证据 | 包名、字节数、摘要、实际验证渠道 | 同左，并记录 Lua/静态回退及方向测试 |

没有验证最低版本时，填写“仅对以下提交核对/实测”，不要猜测一个最低支持版本。未测试的项目明确写“未验证”，不要留一个含义不明的勾选框。

## 可复制模板

将下列文本复制并替换尖括号内容，删除不适用项。包内 `lockscreen.json.version` 始终遵循 schema，不使用这里的发布版本替换。

```markdown
# <扩展名称>

<解决什么需求，在哪个页面或时机使用，主要效果。>

## 版本与兼容性

- 类型：<普通 Lua 插件 / 静态锁屏 / Lua 锁屏>
- 发布版本：<例如 1.0.0>
- 源码提交：<扩展源码提交>
- 固件依据：<从设备“关于”取得的实测版本；没有源码权限不必填内部提交，不猜最低支持版本>
- 硬件与尺寸：<型号、固件端口、逻辑分辨率、方向>
- 验证状态：<仅源码核对 / 结构检查 / 宿主回归 / 实机，日期>

## 安装与更新

<支持的安装渠道、准确 SD 路径、设备菜单操作、是否需选择为当前模板。>
<目录/本地包/云市场的资源差异；更新时私有数据如何保留或迁移。>
<卸载位置，以及是否会删除个人数据；未确认的行为明确标注。>

## 文件与资源

<源目录树、入口、包内路径，以及发布资料中未入包的说明/截图。>
<字体来源、系统字体依赖、图集字符、PNG 格式与授权许可证。>

## 接口与配置

| 接口或字段 | 使用方式/取值 | 缺失、失败或不支持时的行为 |
| --- | --- | --- |
| <例如 storage.write 或 clock.now> | <完整签名、单位、索引基准> | <false/nil 的兜底> |

<普通插件：title/navigation、实现的回调、实际接收事件、存档路径与格式。>
<锁屏：canvas、area、when、interval_ms/hold_ms、JSON 与 Lua 刷新方式。>
<config 自定义 key 的来源及默认值；是否需要 ANCS、诗库或已校准时间。>

## 操作说明

<用户如何开始、点击/滑动/导航如何作用、如何退出或解锁。>
<若当前固件没有转发硬件 key，不把它写成插件操作。>

## 刷新、资源与数据

<何时绘图、何时请求刷新、tick 节流/局刷范围、BLE 与功耗观察。>
<写入数据、路径、单值大小、保存时机、失败处理；无数据时写明。>
<锁屏通知只读，不声称有网络/任意 BLE/SD 访问。>

## 构建与打包

<以自己的工作目录为起点，使用文档下载的 justread_pack.py 给出可复制命令，不依赖私有固件仓库。>
<工具检查覆盖范围，以及仍需设备验证的内容。>

最终产物：<文件名>，<字节数> bytes
SHA-256：<最终产物摘要>

## 验证记录

| 场景 | 输入/步骤 | 预期 | 实际结果与证据 |
| --- | --- | --- | --- |
| <首次打开或锁定> | <目标设备/固件与操作> | <显示> | <日志/截图及日期，或未验证> |
| <缺失数据/资源> | <条件> | <兜底> | <结果> |
| <退出/解锁与再次进入> | <操作> | <恢复/保存> | <结果> |

<分开记录自己的包检查、实机、市场扫描与审核；内部宿主回归仅由有权限的维护者补充。>

## 已知限制与排错

<例：本地 .jrpack 无法正常私有存储、图标仅目录读取、未校时显示 --:--。>
<错误表现、相关日志 tag、恢复步骤、反馈时需要的版本与信息。>

## 变更与授权

<版本变化、存档/接口兼容性、第三方代码/字体/图片许可证。>
```

## 新增接口时的维护约定

扩展作者只能使用宿主已提供的接口。固件维护者增加 API 时，需要同步记录：普通插件还是锁屏可用、签名及类型、单位/范围/默认值、返回值及错误行为、允许回调阶段、平台 callback 是否可缺失、CPU/内存/I/O 影响、可运行样例与验证状态。

更新头文件/实现、对应开发页、打包器/市场规则及示例，保证调用者不会因同名 API 或安装方式差异得到错误预期。设计草案接口应单独标记，不写入已实现 API 表。
